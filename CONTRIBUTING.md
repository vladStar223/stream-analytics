# Руководство по разработке (Workflow)


## 🌿 Правила совместной работы (Git Workflow)
Для исключения конфликтов и поддержания прозрачной истории коммитов разработка ведется по модели **Feature Branching**:

1. **Ветка `main`** — стабильная рабочая версия проекта. Прямые коммиты в `main` не делаются.
2. **Создание фиче-веток:** под каждую задачу или компонент создается отдельная ветка от `main`:
   - `feat/<название-фичи>` (например, `feat/clickhouse-schema`, `feat/generator-logic`, `feat/superset-dashboard`)
   - `fix/<название-бага>` (например, `fix/compose-network`)
3. **Осмысленная история коммитов:** сообщения коммитов пишутся в формате Conventional Commits (`feat: ...`, `fix: ...`, `docs: ...`, `refactor: ...`).
4. **Слияние через Pull Request:** после завершения работы над веткой создается PR в `main`, проверяется вторым участником команды и вливается.
